## 問題 1：NDLOCR-Lite（uv trampoline）が、起動のしかたで落ちる【重要】

- 症状：`error: uv trampoline failed to canonicalize script path`（exit 1）。**902 冊が 2 秒で失敗**（`NDLOCR-Lite failed (exit 1)`）。born-digital の本だけ成功するので気づきにくい
- 起きる時：変換プロセスを **WMI（`Win32_Process.Create`）や `explorer.exe <bat>` から**起動したとき。PowerShell の `Start-Process` からは動く。同じ環境変数・同じ cwd で `subprocess.run('ndlocr-lite --help', shell=True)` を試すと動く（親プロセスの違い）
- 直したいこと（案）
  1. NDL を **trampoline の exe ではなく、その tool の python で `-m`** で呼ぶ（`NDLConfig.command` の既定を `"<uv tool dir>\ndlocr-lite\Scripts\python.exe" -m ndlocr_lite …` のように解決する／`init-config` で実パスを書く）
  2. 起動前に `ndlocr-lite --help` を 1 回試し、落ちたら**バッチ全体を止める**（902 冊を失敗として流さない）。連続 N 冊が同じ原因で失敗したら止める
  3. `batch_report.json` の失敗を「原因の種類」でまとめる（同じエラーが 900 件なら 1 行で）
- タスクスケジューラで夜間運用（docs/batch-operations.md）でも同じことが起きる可能性あり → 要確認

## 問題 2：作業用のページ画像で C ドライブが埋まる

- `work/<book>/pages/page_*.png`（300dpi）が残る。19 万ページでは数百 GB。ラッパーで本ごとに消している
- 案：`--keep-pages/--no-keep-pages`（既定は、`.jisui` を書いた後に消す）。`--no-engines` で作り直すときに要るなら、必要な時だけ描き直す

## 問題 3：アプリ（Claude）の再起動で子プロセスごと止まる

- 長い変換を Claude Code から `Start-Process` で起動すると、アプリが再起動したときに一緒に止まった（エラーなし。`run.log` は途中で切れる）
- 案：`fullocr batch` に **自分で再開する仕組み**（`--watch` で止まったら続きから／ロックファイルで二重起動を防ぐ）。タスクスケジューラ例は問題 1 を直してから

## 問題 4：小さい本の固定時間

- 28 ページの本で 515 秒、32 ページで 342 秒。1 冊の固定 約 80 秒以上（Docling のモデル読み込み・Gemini 2 往復）
- 案：`batch` で **Docling・NDL を 1 プロセスに常駐**させて本ごとの読み込みをなくす／Gemini は後でまとめて（`postprocess` 一括）

## 追記（2026-11-24）問題 5：大きい本（2,622 ページ）で Docling が MemoryError

- 本：太田 脳神経外科学 12 版（1 ページずつの PDF 2,622 個をつないだ 1 冊）。RAM 24GB、本全体の一括変換と同時に動かした
- NDL（約 6 時間）は通ったが、その後の `docling convert` が `MemoryError` → `pyo3_runtime.PanicException: PyObject pointer is null`、exit 1。`run` 全体が失敗し、NDL の結果も使われずに終わった（21,512 秒）
- 案
  1. Docling を**ページの区切り（例 200 ページずつ）**で回して JSON をつなぐ（`DoclingConfig.page_chunk`）。IR はページ番号で合わせられるはず
  2. 構造エンジンが落ちても **NDL だけの IR（フォールバック）で Markdown と .jisui を作る**（見出しは平らでも、本文と原文ページの行き来はできる）。今は全部失敗になる
  3. 失敗しても NDL の結果は work に残るので、**`--resume-from structure`**（NDL をやり直さず構造から）を作る
- 11 版（上 1,306・下 1,492 ページ）も一括変換の順番待ち。通るかどうかで、区切りの大きさの目安が分かる
